# ReadWeave 查证、格式与阅读交互迭代

## 范围与基线

基线为 `146c55f453d5add538851ff3de0743d8fb32c73f`，本计划先于实现登记，不代表验收已通过

用户确认的费用上限：普通问题 ¥0.05，困难问题 ¥0.10；不自动充值或更换模型

## 调查结论

| 用户问题 | 已确认的代码原因 | 修改方向 |
| --- | --- | --- |
| 猜名称来历、缩写展开 | writerSystemPrompt / writerInput 同时要求“不得猜测”和“必填字段允许常识补齐”；没有针对缺失事实继续查证的循环 | 命名事实必须有直接引文；按缺口继续检索，记录停止原因，禁止拼造全称 |
| 已生成被等同于已核实 | 当前 qualityState 在正文非空且没有预算问题时写入 verified；repairRounds 固定为 0，独立核验为 not-run | 分开记录交付状态、格式结果和事实核实状态；不能用模型自报 high 或来源 ID 存在证明事实正确 |
| 格式不稳定 | formatReadWeaveBody 对全文替换标点、合并单换行、把超过四段的内容合并；ReadableBody 只把文本放进 p 标签 | 保护代码、URL、公式、引用；格式规则统一编号；保留结构；安全渲染 Markdown |
| 草稿读后灭灯 | viewed 接口直接清除 ready-for-review 的 unread | 草稿绿灯由未保存状态决定；保存成功再清除 |
| 模板莫名选中 | activeTemplateId 只在点击模板时更新，编辑问题和切换上下文不重算 | 根据当前光标所在问题与模板的精确匹配计算高亮 |
| 回答不可选、追问挤占侧栏 | 正文继承 body 的 user-select:none；beginFollowUp 替换侧栏状态；深度上限为五 | 回答独立选区；独立浮窗；父回答先保存；服务端限制三层 |
| 要点仍是手写 | commons、生成入口和界面都把 key-point 判为 manual | 新总结走生成路径；保留旧手写对象，不改写历史数据 |

## 顺序与产出

1. 查证：保留 Serper、Exa、Jina 适配器，增加每题共享预算、缺口查询与证据定位；只扩大未解决部分，不以结果数量证明事实
2. 写作：去除冲突指令；名称来源与缩写不得用常识填充；格式合同与局部检查共用规则，格式修复最多两轮，不自动重写整个回答
3. 状态：未保存草稿保持绿色；保存失败保留绿色；模板点击、编辑、换问题、切换选区都重新计算选中状态
4. 追问：原回答为第 0 层，可创建第 1–3 层追问；父回答保存成功后才能创建子任务；父子关系和选区在服务端校验；浮窗状态不覆盖侧栏
5. 类型：显示顺序为问题、定义、注解、总结、笔记；注解只扩写旁路解释，总结提炼选区内知识点，笔记保持手写
6. 验证与交付：定向单测、独立内容题集、浏览器交互、类型检查和构建；轻量差异审核、普通推送、候选同镜像验证后上线

## 查证与格式边界

- 最多 20 次有效检索或页面读取；不把重复请求或读取缓存当成新增查证；查到即停、预算先到即停
- 普通问题不强制跑满检索；困难问题只补查缺失的必答事实
- 搜索服务错误、预算耗尽、来源没有说清楚分别记录，不能把前两者说成“全网查不到”
- 搜索关闭时不绕过开关；同一来源转载不算独立佐证
- 引文存在只能证明引文确实出现，不能自动证明整个推论正确；事实评估与格式测试分别验收
- 命名来历、正式展开、年份、数值、身份不允许自由猜测；不适用的定义维度不编造内容
- 新格式规范优先于旧的“四段以内”等限制；定义保持一个连续文本块，单个定义不开列表头
- 网址、代码、逐字证据、数字、否定与适用条件不能因格式修复改变
- 注解与总结生成的都是旁路回答，不改文章正文；历史手写要点继续以手写来源读取

## 已执行的只读复现

直接从基线 TypeScript 提取原有纯函数，转译后调用 formatReadWeaveBody，不调用模型、不修改生产

| 输入 | 实际输出 | 结论 |
| --- | --- | --- |
| `资料：https://example.org/a?x=1&y=2` | `资料：https：//example.org/a?x=1&y=2` | URL 的协议冒号被破坏 |
| 行内代码 `const x = {a: 1};` | 行内代码 `const x = {a： 1}；` | 代码标点被破坏 |
| 冒号及三个已有列表项 | 换行及缩进保留 | 该路径可复用，不能为了改其他格式把它破坏 |
| 五段分别为甲、乙、丙、丁、戊 | 前两段合并为甲；乙，共四段 | 固定段落上限会改写结构 |

上述是缺陷复现，不是修复后的通过证据

## 实施细节

### 查证

- 先区分对象正式名称、论文标题、缩写展开和命名来历，四者不能互相替代
- 证据记录保留来源 URL、原文引句、对象、支持的事实项、时间范围和检索时间
- 名称来历和缩写展开只接受来源明确说明；仅有相同字母、相近词语或论文标题不能当作命名证据
- 缺口检索优先对象主页、官方仓库及文档、原论文和作者材料，再扩展到独立来源；读取与缺口相关的正文窗口，不只截页面开头
- 每次请求前预留费用，所有并行搜索共用余额；为最终写作和必要的局部修复保留额度；不能调用完才检查超支
- 已生成、待保存与事实已核实是不同状态；绿色只提醒未保存，不能作为事实准确性证明
- 检索次数、页面读取次数、缓存命中、预算预估和服务返回用量分别记录，不把硬编码价格估算称为实际账单
- 达到 ¥0.10 仍不足 20 次有效查证时，以预算上限为准；不得声称已完成 20 轮或“全网没有答案”

### 格式

- 将用户提供的顶层规则按规则编号整理为版本化项目合同，区分程序可判定规则与语义规则，禁止运行时拼接互相冲突的旧规则
- 程序可判定项包括受保护区域、标点边界、空行、列表语法、双语结构和损坏标记；语义项包括官方名称真伪、信息遗漏和并列关系
- 使用结构感知的处理及渲染，不对全文执行统一正则替换；实际 Markdown、代码、公式和列表渲染纳入浏览器验收
- 每个补丁绑定旧文本及位置，只改命中的最小完整单元；旧文本不匹配或影响受保护事实则不应用
- 最多两轮局部修复；格式问题不以无限重试、整篇重生成或禁止用户保存收尾
- 对比原始模型输出、修复后输出、最终渲染，定位规则失败发生在哪一层；不在没有同题对照证据时归咎于某个模型

### 追问与保存

- 未保存答案的选区操作提供“保存并追问”，调用现有保存事务；只有收到成功的 linkId 后才创建子任务
- 保存失败时不创建子任务、不扣生成费用，保留原答案和选区
- 父回答身份、版本、选中文字和局部定位一起传递；拒绝不存在的父回答、跨文章绑定及第四层请求
- 新建深度限制三层，旧的四、五层历史数据保留可读，不删除用户内容
- 独立浮窗支持关闭、重新打开和中断；鼠标进入浮窗不让它被 hover 离开事件关闭
- 在富文本渲染后的答案里选区时，定位到对应源片段；相同文本多次出现必须保留偏移和前后文，不选错另一处

### 质量题集

- 用户提供的命名错误属于开发回归样例，不参与独立质量成绩
- 另设 40 个跨领域固定案例：正式展开、非缩写专名、未公开来历、相似主体、当前/历史身份、来源冲突、定义、扩写、总结及多媒介格式
- 对查证完整性、事实支持、直接回答、格式合规、原文保真分别评分；不得只靠某个模型给自己打总分
- 固定搜索与模型响应验证程序路径，不能代替真实模型质量验证；真实调用按已确认额度执行，分别记录通过或阻塞原因

## 验收

- 命名、缩写、相似对象、过期来源、来源冲突、关闭搜索、取消和预算边界均有固定夹具；用户给过的例子只算回归，不算独立泛化题
- 受保护字符逐字不变；格式处理幂等；列表、代码、公式、标题、定义均检查实际渲染
- 草稿查看、刷新、保存失败后仍绿；保存成功后熄灭；不新增空闲轮询
- 模板高亮与当前问题精确一致；模板替换与末尾追加分别测试
- 鼠标、键盘、触屏选择回答文字；未保存父回答不能开始子生成；第 4 层服务端拒绝且零模型调用
- 追问浮窗不覆盖侧栏问题或草稿；关闭浮窗不丢已生成内容；重复点击只创建一个子任务
- 总结默认不联网扩展选区事实，保留关键条件、否定、数值与关系；旧要点内容不变
- 只读和编辑文章正文前后不变；无重复正文 PUT、无未处理页面错误
