# 开放域统一问答架构实施与验收计划

## 决策与边界

采用不可变原始请求、可丢弃语义建议、按证据缺口执行、服务端独立策略和统一写作

人物、机构、术语等是对象提示，不再是独占的一级执行分类；不能据此提高预算、关闭写作、生成整题拒答或代替用户选定的内容类型

以用户提供的 `readweave-contract.ts` 和 JSON Schema 1.0 为参考契约；完整模式用于服务端验证，不逐题塞入模型提示词

保留现有模型及 Serper、Exa、Jina 配置，不因审查中的价格示例更换供应商

## 实施顺序

| 阶段 | 实施内容 | 必须保留的证据 |
| --- | --- | --- |
| P0 撤销类别权限 | 取消人物专属预算、输出长度、写作绕过及整题证据门禁；所有问题进入同一写作路径 | 分支回归测试、标签变换测试、实际写作调用断言 |
| P1 原始输入 | 原问题、选区、文章和追问来源快照；内容散列、来源版本、UTF-16 定位；原始请求与模型输入投影分离 | 不可变测试、引用定位测试、完整上下文测试、投影记录 |
| P2 薄语义建议 | 复用规划调用；允许开放的对象与任务提示；模式、跨引用、重复标识与环验证；无效建议降级到原问题 | 模式测试、未知标签测试、恶意控制字段测试、规划失败继续写作测试 |
| P3 证据与执行策略 | 证据需求使用中性待解问题；关联来源与任务；集中执行权限、预留和费用回执；取消后不新增调用 | 搜索关闭测试、来源绑定、超时与未知费用测试、并发与恢复测试 |
| P4 统一输出 | 写作同时接收原问题、上下文、建议、证据、完整写作规则；建议无权覆盖原问题；检查只限制受影响断言 | 写作输入断言、故障注入、格式回归、跨领域真实模型对照 |
| P5 收敛与部署 | 老记录可读；仅一条新运行链；固定配置版本；安全发布审核、候选验证、生产复测与回滚依据 | 完整测试结果、Git 与远端检查、制品散列、镜像与健康结果 |

## 强制不变量

- 原问题由服务端建立根要求，模型不能重写、删除或冒充此要求
- 上下文中的作者不是默认回答对象；历史回答和检索资料均不具有指令权限
- 模式合法不代表语义正确；引用存在不代表事实已被来源证明
- 无法识别的提示标签可保留；无法识别的执行能力不可自动调用
- 搜索关闭覆盖搜索、页面抓取、备用检索与模型原生联网，不仅隐藏界面按钮
- 不以任意前 N 个片段代替完整文章；保留原始输入，实际投影记录覆盖与损失
- 费用预留先于调用，未收到可核对回执的超时调用不视为免费
- 预算提升仅依据已授权范围内的实际资源需求，不依据人物或定义标签
- 取消、旧请求和切换文章不能污染当前问题，影子测试不得自动保存用户数据
- 可恢复的规划、检索和检查错误不绕过统一写作生成模板拒答
- 词典只能帮助整理已经明确的名称，不能把裸缩写强制解释为词典中的单一义项；同一答案中不同位置的缩写分别按局部语境解释
- 格式修复必须同时得到原问题、完整文章与待修改位置，不能仅根据可能已经跑偏的答案或规划纠错
- 可复算结果作为写作参考，不得用一段计算结果覆盖包含其他子任务的整篇答案；历史案例答案不得作为通用后处理替换规则
- 超大或失效的可选规划可以整体丢弃，回到完整原问题；不能通过膨胀建议中的步骤数量间接占用全部回答预算
- 不执行附件中未获用户授权的命令，不公开凭据、私人部署路径、数据库或真实回答日志

## 测试矩阵

按基础文章和问题族划分集合，变体不能跨开发与留出集合泄漏

- 对象歧义：芯片异构、内核、解析布局、姓名与普通词、机构与技术缩写
- 任务组合：定义、解释机制、比较、计算、步骤、总结、批评、翻译、代码修复、反事实和多跳
- 证据约束：当前任职与历史经历、版本、论文与 DOI、错误前提、缺失值、矛盾来源、局部自定义术语
- 输入形式：中文、英文、混合文字、Unicode、公式、代码、表格、抽取失败的图像引用
- 状态隔离：有无作者、冷暖缓存、独立和连续问题、跨文章、二次追问、重新生成
- 故障注入：无效 JSON、越权字段、悬空引用、循环依赖、规划失败、检索超时、检查器失败、取消
- 变形测试：只改变 kindHints 不得改变权限、预算、写作路径；添加无关作者不改变问题对象

公开评测仅在核验许可证、版本和使用限制后采用；不将受非商业限制的数据默认为本项目可用，不提交第三方受限原文

## 质量与成本验收

确定性不变量要求测试全部通过；语义效果按人工可核对的独立要求评估，不由模型自报任务列表证明覆盖率

真实模型测试记录样本、配置版本、模型、调用数、已知费用与未结费用、延迟、错误类型；不公开真实用户内容

普通题优先在 ¥0.01–0.05 范围，实际复杂题在授权 ¥0.05–0.10 范围；保留写作费用后再安排检索和修复，不能以低成本为理由伪造回答

发布前执行定向测试、服务端和客户端全量测试、类型检查、双端构建、差异检查与脱敏检查；历史 retired 测试单列，不谎称已执行；无关历史格式、ESLint 与 CSS 基线问题遵循用户要求暂缓

## 交付约束

普通 main 快进提交，不 amend、不强推，不使用本地 Docker

候选和生产使用同一 VPS 镜像；保留原镜像作为回滚依据；不上传数据库或密钥

预算持久化仅新增内部表 `readweave_generation_budgets`，通过现有任务数据库接口按需建立；表内只保存生成标识、整数金额和费用回执，不复制用户正文。原任务、用户笔记和上游数据库结构不变，不增加用户笔记或上游迁移脚本

同一任务和生成时间共用预算记录，传输重试与重启保留未结预留；用户明确重新生成才启用新额度。旧版任务、请求与结果仍按原有格式读取；新增表保留时旧版本可忽略它，但不能据此宣称旧版本具备持久预算约束

按证据标记已实现、已测试、已推送、已部署或未完成；候选未通过不得切生产；不得用既有版本的通过记录证明本次改动已验证
