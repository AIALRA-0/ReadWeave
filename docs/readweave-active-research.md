# 主动获取与陈述式回答流程

## 当前生产入口

`generateReadWeaveAnswer` 与管理端试运行进入 `generateReadWeaveActiveAnswer`

原有领域分类、默认构造流、模板式拒答和独立内容审判不再控制生产生成路径
旧执行器仅保留隔离测试兼容入口，生产调用旧导出也会进入新流程；这不代表历史代码已全部删除

## 执行顺序

```text
原问题与可访问的完整资料目录
  → 模型主动读取必要语境
  → 陈述式原子事实需求
  → 缺口分析、搜索与页面读取
  → 事实、来源与有依赖顺序的陈述式构造流
  → 用户审核或自动采用
  → 再检查缺口，必要时补资料并更新构造流
  → 根据全部问题、资料、构造流与完整写作技能写作
  → 确定性局部排版和模型格式修复
  → 返回正文与真实执行记录
```

每个模型阶段均使用同一资料获取协议，资料动作与阶段结果不能在同一次响应中同时提交
已检索不等于全部需求已有资料，但没有新缺口时不要求重复付费搜索
格式修复不重新判断问题类别，不以证据数量或外部审查建议替换答案

## 资料范围与隔离

- 资料工具依次覆盖片段、关键词定位、相邻段落、章节与全文
- 当前片段携带全文位置，重复文本不靠字面猜测章节；章节按标题层级包含子节，并在下一个同级标题前结束
- 文章用于确定含义和前提，不是一般知识解释的上限
- 外部页面完整保留，先返回完整章节目录，再读取所需章节；不按前若干字符截断页面
- 已读取的相同正文只输入一次，重复检索直接返回已有记录
- 释放正文前必须保留相关事实与来源映射，原始资源仍可重新读取
- 每次问题独立持有资料状态，不继承其他文章的领域结论
- 外部材料中的指令不能改变工具权限、用户问题或预算
- 搜索关闭时，不调用搜索服务或外部页面读取

## 审核与续写

关闭自动采用后，服务端先生成真实构造流，任务进入 `awaiting-plan`
此时不调用写作模型，也不执行自动保存

确认同一问题后沿用原任务、资料、检索去重记录和预算周期
修改必答项、目标或排除项时重新分析需求，但复用已有资料
改变问题、文章片段或搜索开关则不复用旧研究状态
服务端研究快照不返回浏览器，也不从请求中接收

## 写作与格式

写作和格式阶段均接收完整技能入口、格式规则、解释框架与公式说明规则
不再只投递技能摘要

格式修改采用定位明确的局部补丁，公式、代码和原样对象不能被改写
已有缩写、中文名和英文名全部出现时，缩写位置可由确定性补丁调整，无须再次猜测全称
未知名称仍需资料确认，不能以格式修复名义编造英文展开
格式修复遵循技能的两轮上限，失败保留原正文并记录残留项，不伪装成全部符合

## 费用与可追溯性

当前按用户授权临时暂停费用上限，生产默认为 `meter-only`，记录每次调用的预留与结算但不按金额拦截研究、搜索、写作或格式修复
历史 ¥0.05 / ¥0.10 保留为账本参考值，界面显示“费用限制已暂停”，不再把它们显示为有效上限
已有任务在下次运行时保留原费用并转为只记账模式，不清空超时待确认记录，也不会自动重新运行已失败任务
需要恢复新任务的费用约束时，由服务端设置 `READWEAVE_BUDGET_MODE=enforced`；已解除限制的旧任务保留其记录和模式
没有额外按阶段百分比分配的输出长度上限
只记账模式下官方服务使用其输出能力上限，未知兼容服务不再收到应用自设的输出长度参数；服务自身限制和用户取消仍有效
官方模型使用固定版本公开词表估算输入并预留协议余量，第三方模型保留明确的保守估算
搜索费用属于配置费率估算，不冒充供应商最终账单

词表只包含公开分词数据，不包含模型权重、密钥或用户内容
来源版本、原始文件哈希及许可位于 `apps/server/src/assets/readweave-tokenizer`

## 验证范围

单元测试覆盖资料层级、完整后文、跨问题隔离、重复检索、搜索关闭、陈述式需求、依赖顺序、用户审核续写、预算周期与局部格式事务
两组各 250 项需求用于确认模型结果不被替换成默认计划

浏览器测试验证真实按钮、任务接口、等待审核、同任务续写与保存链路
固定模型用于功能验证，不作为真实答案质量证明

付费试验单独使用 `vitest.active-eval.config.mts`，仅测试计算内核与大整数两个合成语境，不使用评委模型
原始响应和执行记录必须保存在仓库外，不提交真实模型回答或生产数据
少量成功用例不证明所有文章的回答质量，最终阅读体验由用户在实际文章中检验

## 历史规则的测试迁移

旧版两项测试要求超长语义建议被丢弃并进入默认计划，与当前“禁止语义回退”需求冲突
对应输入规模已迁移到主动流程测试，改为断言全部需求完整保留，而非新增跳过或降低失败等级
