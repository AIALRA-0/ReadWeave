# 技术内容规则

## 1. 适用范围

当前任务出现英文缩写、内部名称、数学公式、数值证据或代码时，使用本文件

## 2. 正式术语

- 原文已经使用的正式术语、英文缩写和内部名称必须保留
- 术语提供可追踪名称，解释提供第一次阅读所需的理解，两部分必须同时存在
- 已有正式英文全称的缩写首次出现时使用“中文全称（English Full Name，缩写）”
- 没有正式展开形式的格式名、产品名和品牌名保留官方原名，再用自然中文说明当前用途
- 产品、品牌、软件、型号、计量单位或其他名称没有自然通行的中文译名时，优先保留官方原生名称，再用自然中文说明它是什么
- 不为满足中文形式而编造生硬音译；准确性、行业惯例和原始名称的可检索性高于逐词翻译
- 英文采用官方大小写，数学符号、计量单位和程序标识保持规范写法
- 读者需要理解技术词才能判断或操作时，首次出现用自然短句说明定义、当前用途、可观察表现和实际结果
- 一份连续文档只在术语首次出现时完整解释一次，各章节直接使用中文名称或原始标识
- 表格、图题、摘要、常见问题和能够脱离正文单独传播的章节需要独立阅读时，保留一句简短解释
- 自动检查器把无法确定的英文术语列为提醒；提醒帮助人工复核，不应为了清零而在每个章节重复定义
- 决定结论的原因和后果保留在正文中，不能只放在悬停说明、脚注或术语表

## 3. 内部名称

- 正文先写普通中文结论，再提供用于核对日志和配置的内部名称
- 内部状态要说明能够证明的范围，以及不能支持的后续决定
- 文件名、脚本名、命令和路径集中放入证据清单，每个独特名称解释一次
- 版本、状态、限制、期限和结果要写明所属工具、任务、文件或交付对象

## 4. 数学排版

- 公式、变量、上下标、上标、希腊字母、不等式和统计符号优先使用数学公式排版语法（LaTeX）
- 行内数学内容使用 `$...$`
- 独立公式使用 `$$...$$`
- 代码、命令、网址、界面原文和逐字证据保持原样
- 统计符号首次出现时要说明名称、用途和当前结论

## 5. 数值来源

- 精确数量、测量值、日期、时长、金额、百分比、阈值和配置值优先使用阿拉伯数字，例如把 `四百二十六个` 写成 `426个`
- “第一步”等操作顺序、固定短语、专有名称和逐字证据不做机械替换
- 引用外部资料时，在数值附近使用顺序引用编号，并在文末提供完整来源
- 计算结果要写明输入数值、公式或换算方法
- 软件产生的数值要写明系统、界面、日志、配置文件、仪器或记录名称
- 用户提供的数值要写明“根据用户本次提供的数据”
- 经验值和估计值要说明经验样本、适用条件或不确定范围
- 同一来源覆盖一组连续数值时，可以在这组数值前统一说明
- 来源无法确认时标记为“来源待核对”

## 6. 关系性数值

- 新数值首次出现时，说明统计范围、筛选条件、记录位置或测量方法，让读者知道为什么是这个数值
- 一个数值由其他数值展开、汇总、去重或换算得到时，依次展示输入、关系规则、代入公式和结果
- 多通道对象展开为独立对象时，列出各通道数组成，并验证对象数量和展开数量
- 多组数据合计时，列出各组数量或小计，并展示求和公式
- 位、字节和存储容量之间换算时，展示每一步除数，不能只给近似结果
- 统计“45种形状”这类去重数量时，写明统计字段、纳入范围、排除规则和去重表达式
- 公式优先使用数学公式排版语法，正文紧跟一句话说明计算结果支持什么判断

## 7. 代码注释

- 所有面向用户展示的代码都需要注释
- 命令、配置项、键值项和彼此独立的语句属于列表式代码，每个能够独立产生作用的代码行都使用该语言允许的同行注释
- 函数、类、条件、循环、查询和界面组件属于段落式代码，每个真实逻辑段开头使用该语言允许的独立注释
- 不能用一条总注释代替多条独立语句，也不能只注释重要行
- 注释说明命令或逻辑是什么、为什么执行、关键输入和可观察结果，不复述代码字面内容
- 注释不得破坏语法和可执行性
- 严格数据格式无法合法加入注释时，交付原文件链接，再提供带注释的等价示例

## 8. 技术内容检查

- 检查原始术语是否保留，并在首次出现处获得自然解释
- 检查同一连续文档是否重复解释同一术语
- 检查英文全称和官方大小写是否准确
- 检查精确数量是否优先使用阿拉伯数字
- 检查原生名称是否因生硬音译而失去准确性或可检索性
- 检查数学记号是否准确
- 检查每个决定结论的数值是否有明确来源
- 检查每个计算结果是否能够根据正文重新计算
- 检查关系性数值是否展示完整过程：
  - 输入
  - 关系规则
  - 代入公式
  - 结果
- 检查汇总数量是否说明完整统计口径：
  - 统计范围
  - 筛选条件
  - 去重方法
- 检查每个代码块是否采用列表式同行注释或段落式开头注释
