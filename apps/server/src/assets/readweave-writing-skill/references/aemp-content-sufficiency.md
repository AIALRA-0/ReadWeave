# AEMP 内容充分性与视觉叙事

## 1. 使用范围

需要确定读者任务、首屏内容、变化说明、决策材料、状态页面、审计材料、项目解释或 AEMP 界面时使用本文件

本文件决定内容是否足够以及先展示什么，不扩大用户要求的技术范围

## 2. 内容充分性判断

形成内容前确认：

- 当前读者是谁
- 读者现在要完成什么任务
- 当前内容属于教程、操作、参考、解释、决策、状态、审计还是项目变化
- 读者必须理解什么
- 读者必须看到什么事实
- 读者必须决定什么
- 读者必须验证什么
- 哪些内容当前不需要
- 哪些内容只会增加噪声
- 首屏允许多少节点、文字和选项
- 细节从哪里下钻

这份判断默认不作为正文输出；用户要求审计内容充分性、编写模板或定义机器合同时才展示结构化结果

材料不足时，不得用更多解释填补事实缺口；正文写明已知事实、缺失内容、实际影响和取得下一条证据的方法

## 3. 七种内容任务

### 3.1. 教程

帮助不熟悉主题的读者完成一次可验证学习过程；正文包含起点、最小背景、连续练习、可观察结果和理解检查，不能把完整参考手册塞进教程

### 3.2. 操作

帮助已经知道目标的读者完成具体动作；正文包含前置条件、连续步骤、成功表现、失败处理和回退边界，与当前动作无关的原理移入解释或参考

### 3.3. 参考

帮助读者快速查询准确事实；正文包含稳定名称、字段或接口、允许值、约束、示例和版本范围，不强迫读者按照教程顺序阅读

### 3.4. 解释

帮助读者形成能够预测系统行为的心智模型；正文说明组成部分、真实输入怎样到达输出、关键取舍、失败链和证据边界，解释不能冒充运行验证

### 3.5. 决策

帮助有权决定的人在候选方案之间作出选择；首屏先写当前决定、推荐选项、决定依据、主要代价、剩余未知和不决定的后果，详细证据和被放弃方案进入下钻层

### 3.6. 状态

帮助读者立即知道现在发生什么、是否需要介入和下一步是什么；首屏先写当前阶段、负责人位置、阻断、证据状态和当前决定，提交摘要、内部编号和原始日志不得占据首屏

### 3.7. 审计

帮助复核者判断结论怎样形成、证据覆盖什么和哪些内容仍不能确认；正文把具体主张连接到来源、时间、验证方法、限制、冲突和责任人，单独一句“已经全面检查”不能成为审计结论

## 4. 项目变化

解释项目变化时按照下面顺序组织：

1. 这次为什么动
2. 原来怎样工作
3. Agent 实际去了哪里
4. 结构和数据流怎样变化
5. 用户现在得到什么
6. 还有什么没弄清楚
7. 用户现在需要决定什么

七项是项目变化页面的叙事顺序，不是每个聊天回答的固定模板；没有真实候选快照时明确写候选尚未冻结，没有需要用户决定的内容时不制造选择题

## 5. 三层展示

内容较复杂时最多使用三层语义：

- 第一层回答读者为什么看、现在怎样、得到什么、未知什么和需要决定什么
- 第二层展示结构、路径、约束、证据摘要和前后变化
- 第三层展示原始事件、命令、文件、摘要值、版本差异和完整审计记录

层级限制约束单次视图，不限制读者继续下钻；首屏不得用技术统计代替实际解释

## 6. 主张和证据

证据按照实际来源显示：

- Agent 这样说
- 已看到代码变化
- 已由静态分析确认
- 已通过指定验证
- 已在运行中观察
- 已由负责人确认

等级由来源和验证方式决定，Agent 不能自行把自己的说明升级成已验证结论；证据必须绑定具体主张，同一节点的其他测试通过不能证明这项主张成立

证据缺失时显示未知；证据互相反对时显示冲突；超过适用时间或版本时显示过期；结论同时说明证据能够证明和不能证明的范围

## 7. 删除测试

交付前逐项检查句子、标签、卡片、图例和统计：

> 删除它以后，读者的理解、判断、行动、证据边界或下一步是否改变

如果五项都不改变，删除该内容或移入更深一层

保留内容至少承担一种作用：

- 改变读者对事实或因果的理解
- 改变当前决定
- 改变下一步行动
- 说明证据能够覆盖的边界
- 暴露风险、冲突或未知
- 提供完成操作所需的准确值

## 8. 视觉和文字分工

三个以上节点、分支、参与方、重试或返回关系优先使用从上到下的 Mermaid 或交互图

图负责展示结构、顺序、关系和状态；文字负责解释原因、证据、代价、未知和决定

图中节点使用用户能够理解的行为名称；完整命令、文件路径和内部字段放入对象详情；颜色不能成为唯一状态信号
