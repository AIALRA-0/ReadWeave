# 复杂报告规则

## 1. 适用范围

当前任务需要完整报告、审计材料、工程复盘、交接文档或其他长篇交付物时，使用本文件

## 2. 报告叙事

- 报告先确定读者需要作出的决定，再选择章节
- 用户直接询问完成状态时，开头先回答完成范围，随后提供依据
- 普通分析按照“事实或原因 → 实际后果 → 结论或行动”推进
- 每一节只解决一个问题，章节开头可以概括本节结果，下一段立即提供证据
- 主体、因果关系和证据边界在段落层面完整即可，相邻句子不重复申明同一事实
- 每个后续句子需要增加新证据、新后果、新行动或新结论；没有信息增量的句子应当删除或合并
- 删除“本项目的准确表述如下”等删去后不影响事实和逻辑的引导句
- 同一边界说明在一个解释单元中完整写一次，后文直接引用已经确定的范围
- 失败记录要说明触发原因、影响范围、隔离方式和当前状态
- 剩余风险要写明产生风险的缺失证据，以及补齐证据的负责人和行动

## 3. 推荐顺序

- 第一步，写一句能够直接回答完成范围的结论

- 第二步，用短段落概括成功结果、失败结果、证据范围和剩余事项

- 第三步，按时间或因果顺序说明执行过程

- 第四步，分别说明失败、隔离措施和恢复过程

- 第五步，汇总结果矩阵、数值来源和证据索引

- 第六步，写明复现方法、发布边界、责任人和后续工作

## 4. 大型任务防漂移

- 写每一节前重新确认本节主体、依据、后果和行动
- 一节写完后先检查本节，再继续下一节
- 全部章节拼接后必须重新检查全文，分节通过不能代替全文通过
- 同一禁用句式在相隔较远章节中重复出现时，每一处都要独立修复
- 修复否定先行转折时，重新安排事实顺序，不能只替换连接词
- 正文、表格、图题、注释和结论都属于检查范围

## 5. 编辑过程边界

- 最终报告只写报告对象的事实、证据、判断、风险和行动
- 作者编写进度、未来补写计划和临时占位内容不得进入最终报告正文
- 材料不足时，写明当前已经核实的证据、证据缺口和补齐负责人
- 用户明确要求写作进度、修订日志或编辑流程时，可以单独汇报对应过程；这类过程信息不能混入正式报告正文

## 6. 报告交付

- 报告中的结论能够在不查看术语表时直接理解
- 报告中的原始术语仍能用于搜索日志、核对配置和复现结果
- 每个表格、图形、引用、公式和代码块都满足对应按需参考文件
- 报告正文没有汇报已经写到哪里的文档状态、占位说明、未来补写计划或章节编写进度
- 最终完整正文通过 `scripts/Test-HumanReadableChinese.ps1` 后才能交付
- 检查通过后发生任何改动时，重新检查修改后的完整版本
