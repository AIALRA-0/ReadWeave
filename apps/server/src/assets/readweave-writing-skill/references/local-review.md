# 本地检查与补丁用法

只有用户明确要求检查、验证或复测，当前任务把新建或修改的本地文档作为正式交付物，或者现有本地文档需要精确补丁以避免破坏未命中内容时，才在本地工具可用的前提下读取本文件；纯聊天回答默认不创建临时文件，也不因为能够访问文件系统就运行检查器；这是已有两份规则的执行方法，不增加文风要求

## 保存与检查

在当前任务可写的临时目录保存完整内部初稿，文件使用 UTF-8 编码；不要保存到技能目录，也不覆盖用户提供的原件

用当前技能中 `scripts/review_writing.py` 的实际绝对路径替换下面的 `SCRIPT`，初稿、输出和报告使用当前临时目录的不同文件

```text
python -X utf8 SCRIPT --input draft.md --report check.json
```

默认按用户的紧凑列表检查；若当前宿主的更高层指令明确要求每个新嵌套列表前空一行，所有检查和修复命令加 `--nested-list-spacing host-required`，报告保留这一适配选择；只保留新子列表前的必要空行，同级项目之间仍不随意加空行，不因助手个人偏好启用此选项

当前任务有内容图片且能取得实际路径或网址时，每次命令为每张内容图加 `--source-image "实际地址"`，程序核对正文中是否保留该图片对象及非空替代文本；普通链接不算保留图片，程序不访问网络、不生成替代图，也不判断图片解释是否正确；没有可用地址时不编造地址，仍人工核对原对象

有具体依据确认仅作排版或间距的透明占位资源不作为 `--source-image` 的正文内容图输入，仍在原件和资源清单保留原始字节、来源与用途依据；这不是删除资源的许可，不能仅凭尺寸、文件名、颜色或加载失败免查，也不能将有效图片改为空替代文本以逃避解释

初稿把图片地址抄错时，可将这一完整图片对象作为最小替换单元，把地址修正为本次 `--source-image` 明确提供的地址，替代文本和题注保持不变；已确认的原图不能换成另一张原图，代码或逐字引用里的图片写法仍受原样保护；已确认原图的空替代文本可以局部补齐，准确性由助手据图复核

检查报告的 `format.findings` 是确定错误，`format.candidates` 是需要按语境判断的疑点；`PASS` 只说明已运行的机械检查没发现问题，不代替两份规则的正文复核

读取报告时按需要选取摘要、发现或行节点，不把整份报告与规则文件混在一次输出里；工具提示截断时补读尚未看到的部分，不能把已截断的规则复读算作完整复读

疑点会定位含连接词的普通段落与列表项，以及本篇已正式定义名称的提前使用和定义内中英文配对；逐项判断它是否确实为独立项目或同一专业概念，成立才局部修改，不成立保留原文，不能把所有逗号机械换行或给日常同名词补术语定义

数字标题的末尾点号检查只提出疑点；先确认它是本次采用的阿拉伯数字层级编号，再按 `1.`、`1.1.`、`1.1.1.` 后接空格局部修复，年份、数量、原文语义编号及受保护文本不自动改动

名称证据、名称内部缩写、标签含义、知识链接目标内容和资源用途由同一助手按两份规则复核；脚本不会查证这些内容，也不会将括号纯净、英文大小写正确或没有报错等同于解释正确；来源记录保留中文与英文及证据位置，无法确认的配对不记为完成，只有影响理解的缺口进入正文

居中扫描只检查可见标记与部分嵌套对齐声明，不能证明渲染结果；有预览条件时展开折叠区域，查看图片与题注、表格与表题是否共用居中容器且实际对象居中，并核对表格内部滚动；外框满宽或页面无溢出不是居中证据，目标媒介不支持时如实说明

同一列表项内的多个问句也会提示复核；问同一件事的改述可以连续，分别询问资格、费用、期限或地点等需要不同答案的问题须分项，不能因为都要问同一个人就合并

报告同时提供当前全文摘要 `format.document_sha256` 和精确行节点 `format.line_nodes`，每个节点含编号和保留换行的原文，供局部补丁定位

## 合并一次局部修复

先完成同一助手的语义复核，找出本次发生变化的判断，再核对正文中直接依赖该判断的标题、说明、示例和结论；把同一行的必要改动合为一个提案，把多个直接依赖位置分别写成精确小补丁并放进同一事务，避免只修被点名的一行而留下连带矛盾；原文、数字和所有无关内容保持不变

只读检查不占修复次数；第一次提交前先检查全文，再把已确认的术语、分项、源信息与标点问题放进同一次局部事务，不先只修空白然后才开始看内容；需要程序对齐时可与该次 `--edits` 命令一起加 `--fix-safe`，它产生的安全事务仍占两轮总额，不能另算预算

紧凑提案文件必须只含以下两个字段

- `document_sha256`：复制本次检查报告的全文摘要
- `edits`：本轮局部修改数组，每项只含以下五个字段
    - `node_id`：当前报告的准确行编号
    - `old_text`：从对应行逐字复制的非空原文，必须在该行恰好出现一次
    - `new_text`：只改变命中部分的替换文本，可以插入必要换行和标题
    - `scope`：单字或标点填 `token`，局部词组填 `phrase`，完整命中句或列表项填 `sentence`
    - `reason`：当前规则与具体错误，不能只写“优化表达”

程序把紧凑提案转换成已有精确提交器的完整补丁，仍核对全文摘要、行位置、旧文本、出现次数、重叠和原样对象；不会自动纠正你抄错的原文或摘要

```text
python -X utf8 SCRIPT --input draft.md --edits edits-1.json --output revised-1.md --report check-1.json
```

只需要安全空白、已有注释对齐或生成正文行末中文句号与分号修复时，可以使用 `--fix-safe` 代替 `--edits`，仍算一次修复

已有代码注释的间距交给 `--fix-safe` 按实际字符宽度计算，不凭视觉手改对齐空格；检查已通过的代码块不重复调整间距，只有代码语句确实改变长度时才需要重新计算

原代码与解释副本分别用清楚的标题或就近说明标明用途；程序无法识别的来源角色由助手核对，不能为了消除检查提示给原件加注释，也不能把解释副本冒充原件免查

仅展示输入或返回值的纯数据不是待加注释的算法语句；保留数据原字节并明确这是输入或结果，围栏的语法高亮名称不能单独决定内容角色；程序仍检查带执行语句的代码，不因标题写着结果就免查

明确标为解释副本的代码允许提交注释内容补丁，可可靠解析的代码语句、字符串和缩进仍逐字核对；原代码的原有注释不开放修改，未知语法不猜测处理

正文分项可以移动或重复未改动的行内代码、链接和公式引用，原有对象及出现次数不得减少；这只核对字符保留，含义、对应关系和来源仍须助手复核

## 复验与交付

重新对照规则复读输出文件，程序检查残留和语义问题共用最多两轮修复；第二轮以实际第一轮输出及新报告为依据，不沿用旧行号或旧摘要

局部修复后同时检查命中位置的前后区块和所有直接依赖位置，尤其新列表是否错误并入上一个列表、子项是否失去所属步骤、结论是否仍引用旧判断、同类遗漏是否还出现在其他位置；再对比未依赖该判断的区块，确认没有被顺手优化；检查器没有语义判断权，不能因怀疑就机械拆句或把日常名称强制术语化

补丁失败时整笔未应用，保留输入稿；纠正错误提案也占下一轮次数，不因换一次命令重新获得两轮额度

最后直接交付已经检查过的文件正文，不再整体改写；两轮后格式残留不卡住交付，不把残留写成通过；只有影响理解、操作或安全的实质缺口需要自然说明

无法运行脚本时继续按规则做同一助手自查并交付，不编造执行记录，不要求用户安装整套项目
